# Реестр программных и инженерных рисков v1.0

## Основные классы
| Класс | Риск | Что проверять |
|---|---|---|
| R1 | Неверные исходные параметры | первичный источник, дата, единицы, диапазон |
| R2 | Недостаточная энергетика | средняя/пиковая мощность, накопитель, затмение, резерв |
| R3 | Недостаточный канал связи | link budget, окна, наведение, потери |
| R4 | Ошибка навигации/ориентации | ADCS, датчики, исполнительные органы |
| R5 | Сбой вычислительной системы | watchdog, резервирование, безопасный режим |
| R6 | Тепловая несовместимость | worst-case hot/cold, переходные режимы |
| R7 | Радиационная среда | доза, одиночные события, shielding |
| R8 | Интерфейсная несовместимость | механика, питание, данные, EMC/EMI |
| R9 | Недостаточная верификация | покрытие испытаниями и правильный уровень теста |
| R10 | Зависимость от поставщика | доступность, интерфейс, сроки, замена |
| R11 | Непроверенная автономность | HIL, flight-like среда, отказовые сценарии |
| R12 | Ошибка масштабирования | переход к повторяемой системе без подтверждённых данных |

## Правило доказательности
Каждый существенный риск должен иметь: условие возникновения → наблюдаемый эффект → обнаружение → снижение → верификацию → остаточную неопределённость.

## Ключевой принцип
Успешный запуск сам по себе не является доказательством архитектуры. Доказательством является набор измеренных результатов, позволяющий перенести подтверждённую возможность в следующую миссию.

Статус: BASELINE / количественное ранжирование выполняется после получения mission-specific данных.
