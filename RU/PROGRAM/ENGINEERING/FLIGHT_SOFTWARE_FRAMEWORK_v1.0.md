# Каркас бортового программного обеспечения v1.0

## Назначение

Бортовое ПО рассматривается как критическая часть системы, связывающая управление, данные, автономность и безопасные режимы.

## Архитектурные слои

1. аппаратные драйверы;
2. middleware;
3. управление подсистемами;
4. оценка состояния;
5. планирование;
6. автономные правила;
7. обработка данных;
8. управление связью;
9. диагностика;
10. fault management;
11. безопасный режим.

## Требования

Каждый критический программный компонент должен иметь:
- определённый вход;
- определённый выход;
- временные ограничения;
- обработку некорректных данных;
- поведение при отказе;
- журналирование;
- версию;
- тестовое покрытие.

## Автономность

Автономные функции должны быть ограничены явно определёнными состояниями и переходами.

Для каждого действия фиксировать:
**условие → решение → действие → ожидаемый результат → контроль результата → fallback.**

## Безопасность

Критические команды должны проходить проверки допустимости. Необходимо разделять номинальный контур и аварийный контур.

## Верификация

Минимальный путь:
unit test → integration test → software-in-the-loop → hardware-in-the-loop → системный тест → эксплуатационные данные.

Статус: FRAMEWORK.
