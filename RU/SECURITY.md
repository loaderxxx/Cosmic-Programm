# Безопасность и граница публичной/приватной информации

Этот репозиторий намеренно публичный.

## Никогда не публиковать

- учётные данные
- API-ключи
- приватные контактные данные
- приватные системные промпты
- защищённую ИИ-оркестрацию
- приватную инфраструктуру
- защищённые алгоритмы
- материалы Evidence Vault
- конфиденциальные сведения о партнёрах
- неопубликованные детали изобретений, если публикация может создать риск для интеллектуальной собственности

## Очистка перед публикацией

КЛАССИФИЦИРОВАТЬ → УДАЛИТЬ/СКРЫТЬ → ПРОВЕРИТЬ IP → ПРОВЕРИТЬ ПРИВАТНОСТЬ → ПРОВЕРИТЬ БЕЗОПАСНОСТЬ → ОПУБЛИКОВАТЬ

## Интеллектуальная собственность

Потенциально ценные изобретения должны оцениваться до публичного раскрытия.

Классификация:
- кандидат на патент
- коммерческая тайна
- авторское право / программное обеспечение
- ноу-хау
- открытая публикация
- мониторинг

## Контроль человека

Внешние обязательства, юридические соглашения, финансовые обязательства и необратимое раскрытие информации требуют разрешения человека.

## Восстановление

Приватная каноническая система должна иметь защищённые резервные копии, независимые от этого публичного репозитория.

Публичная документация не заменяет юридическую, инженерную или информационно-безопасностную проверку.
