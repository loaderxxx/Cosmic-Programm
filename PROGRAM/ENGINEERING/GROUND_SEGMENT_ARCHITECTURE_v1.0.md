# Архитектура наземного сегмента v1.0

## Назначение

Наземный сегмент рассматривается как часть космической системы, а не как вспомогательная служба.

## Слои

1. наземные станции;
2. радиочастотный тракт;
3. планирование сеансов;
4. командный контур;
5. телеметрия;
6. обработка данных;
7. хранение;
8. мониторинг состояния;
9. анализ событий;
10. архив и происхождение данных;
11. симулятор;
12. инструменты верификации.

## Командный контур

Команда должна иметь:
- уникальный идентификатор;
- версию;
- время создания;
- время исполнения;
- источник;
- проверку допустимости;
- подтверждение приёма;
- результат исполнения.

## Телеметрия

Разделять:
- heartbeat;
- состояние подсистем;
- предупреждения;
- аварийные события;
- параметры эксперимента;
- диагностические данные.

## Автономность

Наземный сегмент должен поддерживать работу при:
- задержке связи;
- временной недоступности станции;
- потере части телеметрии;
- необходимости перехода аппарата в безопасный режим.

## Данные

Каждый существенный набор данных должен сохранять происхождение:

**аппарат → подсистема → измерение → время → конфигурация → обработка → результат.**

## Верификация

Наземный сегмент проверяется совместно с flight software через end-to-end тесты.

Статус: FRAMEWORK.
