# PUBLIC TECHNICAL KNOWLEDGE MAP

Updated: 2026-09-19

This repository is intentionally public. Its purpose is to document, with sources, how real space programmes are structured and engineered, and to derive a transparent technical programme from that evidence.

## What is public here

- technical baselines of external space systems;
- programme architectures and capability decompositions;
- publicly documented engineering parameters;
- source/document indexes;
- comparison matrices;
- research methods and evidence status;
- Cosmic Programm public architecture, candidate missions and roadmap;
- requirements, verification concepts and open technical questions as they become mature enough to publish.

## Evidence rule

Every important quantitative claim should have an authoritative source. If a parameter is not publicly established, the repository marks it as unknown, estimated, target, or study value rather than presenting it as fact.

## Source hierarchy

1. official programme documentation and user guides;
2. official agency / manufacturer technical pages;
3. official architecture documents and programme publications;
4. secondary sources only when primary evidence is unavailable, explicitly labelled.

## External systems currently covered

NASA: SLS, Orion, Gateway, Human Landing System, Moon-to-Mars architecture.

SpaceX: Falcon 9, Starship.

ESA: Ariane 6, Space Rider, lunar logistics / Argonaut.

Blue Origin: New Glenn and lunar architecture research.

CNSA / China: Chang'e and International Lunar Research Station architecture.

Additional programmes are being added systematically.

## How the research becomes a programme

COLLECT → REGISTER → EXTRACT → NORMALIZE → VERIFY → COMPARE → SYNTHESIZE → REQUIREMENTS → MISSION DESIGN → TEST / VERIFICATION → UPDATE.

A documented fact is not automatically a Cosmic requirement. It becomes a requirement only after capability analysis, dependency analysis, alternatives and mission relevance are established.

## Public/private boundary

The public repository contains reproducible technical knowledge and the public programme architecture.

Proprietary internal methodology, private prompts, hidden decision machinery, confidential partner information and other protected know-how belong in the separate private core repository.

## Current objective

Build a technically serious, evidence-linked space-programme knowledge base first; then use it to derive a coherent, staged Cosmic Programm rather than designing isolated hardware without an architecture.
