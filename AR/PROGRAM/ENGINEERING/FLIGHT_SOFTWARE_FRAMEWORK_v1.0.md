# إطار برمجيات الطيران v1.0

## الغرض

تُعد برمجيات الطيران جزءاً حرجاً من النظام يربط التحكم والبيانات والاستقلالية والأوضاع الآمنة.

## الطبقات المعمارية

1. مشغلات العتاد البرمجية؛
2. البرمجيات الوسيطة؛
3. التحكم في الأنظمة الفرعية؛
4. تقدير الحالة؛
5. التخطيط؛
6. قواعد الاستقلالية؛
7. معالجة البيانات؛
8. إدارة الاتصالات؛
9. التشخيص؛
10. إدارة الأعطال؛
11. الوضع الآمن.

## المتطلبات

يجب أن يتوافر لكل مكوّن برمجي حرج:
- مدخل محدد؛
- مخرج محدد؛
- قيود زمنية؛
- معالجة للبيانات غير الصحيحة؛
- سلوك محدد عند الإخفاق؛
- تسجيل للأحداث؛
- إصدار؛
- تغطية اختبارية.

## الاستقلالية

يجب تقييد الوظائف الذاتية بحالات وانتقالات محددة صراحة.

يُسجل لكل إجراء:
**الشرط ← القرار ← الإجراء ← النتيجة المتوقعة ← مراقبة النتيجة ← الإجراء البديل.**

## السلامة

يجب أن تجتاز الأوامر الحرجة فحوص صلاحية التنفيذ. ويجب فصل مسار التحكم الاسمي عن مسار الطوارئ.

## التحقق

المسار الأدنى:
اختبار الوحدة ← اختبار التكامل ← البرمجيات ضمن الحلقة ← العتاد ضمن الحلقة ← اختبار النظام ← البيانات التشغيلية.

الحالة: إطار عمل (FRAMEWORK).
